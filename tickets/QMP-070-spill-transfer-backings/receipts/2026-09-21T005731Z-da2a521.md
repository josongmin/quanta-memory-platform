## Producer → contract → consumer

- `SpillFailure<Handle>` returns the original owned handle on ordinary pre-commit error. `NoopSpillController` rejects instead of reporting successful persistence. In-memory and redb targets implement the new failure contract.
- `RevocableSpillHandle` carries the entry, semantic charged bytes, store binding and non-clone `ManagedCharge`. `spill_one_into` keeps process-resident bytes charged while an in-process target retains the handle; failure restores the original source entry and FIFO position. `accept_restored` checks binding, broker identity and charge axes. Dropping an unrestored handle retires its charge.
- The redb byte target returns source bytes on error, but commit ambiguity and inventory reconciliation are still open; this receipt does not assert a durable transactional transfer.

## RED evidence

`unavailable_spill_returns_the_only_handle_without_dropping_it` was added before the producer change. The old API failed E0599 because `MemoryError` had no `into_parts` (exit 101), making loss of the consumed handle explicit.
