## Implemented contract

- Reserve admission uses exact total/non-headroom/live-scratch aggregates and
  the affected owner/class slots instead of cloning all live accounting maps.
- Release preflight aggregates only the affected `(axis, charge-kind)` slots.
  A 10K-live-owner test proves a single release performs exactly three axis
  probes and preserves all accounting invariants.
- Scheduler reserved-floor accounting is maintained incrementally. Normal
  reserve/release/rollback/batch paths no longer clone the full scheduler.
- The public benchmark emits repeated p50/p95/p99 latency, throughput,
  lifecycle busy-retry, semantic accounting, allocation high-water and exact
  allocation/deallocation drift for 1/2/8/32-thread read/write/mixed lanes.
- The verifier requires the complete matrix, at least three repetitions, zero
  semantic/allocator drift, bounded absolute p99, and optional same-host
  baseline regression gates. Negative fixtures prove it rejects drift,
  incomplete matrices, absolute latency regressions and catastrophic baseline
  regressions.

## Limits

Wall-clock distributions are host-local. The baseline gate intentionally
ignores sub-10ms throughput samples, applies a 1ms p99 noise floor, and treats a
10x stable-lane throughput collapse as the default catastrophic regression.
Those calibrations prevent microbenchmark scheduler noise from becoming a
flaky merge oracle; tighter product-specific baselines can be supplied through
the verifier CLI. RSS is not used as accounting authority: exact allocator
callbacks and semantic ledger bytes are measured independently.
