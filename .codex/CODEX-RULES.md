## Architecture & Crate Boundaries

`quanta-memory-platform` is a portable, host-independent memory budgeting /
accounting workspace. It is consumed by the Semantica monorepo through a host
adapter (`quanta-memory-host`) that lives **outside this repo**, and it is
designed to be extracted into its own git repository with no rewrites. The crate
graph is the architecture authority.

Allowed workspace edges (strict, acyclic — `core <- facade <- testkit`):

```text
quanta-memory-platform-core    -> (none — pure)
quanta-memory-platform-facade  -> quanta-memory-platform-core
quanta-memory-platform-testkit -> quanta-memory-platform-core, quanta-memory-platform-facade
quanta-memory-host (Semantica) -> quanta-memory-platform-{core,facade}   # OUTSIDE this repo
```

No member depends upward. `core` must not name `facade`/`testkit`; `facade` must
not name `testkit`. The host adapter never appears as a dependency of this repo —
that would invert the direction.

Layout:

```text
crates/
  quanta-memory-platform-core/     # pure hexagonal kernel
    src/api/         # public broker surface: broker, builder, control
    src/application/ # use-case services: controller (pressure), scheduler
    src/domain/      # config, context, errors, ledger (accounting SSOT), policy, stats
    src/ports/       # trait definitions: pin, scratch, store, telemetry
    src/adapters/    # port impls: hdrhistogram, metrics
  quanta-memory-platform-facade/   # feature-sliced portable stores + pipelines
    src/{payload_store,retained_map,revocable_store,transcript_store,publish_pipeline,spill}/
    src/{presets,shared,scratch}/
  quanta-memory-platform-testkit/  # conformance / chaos / alloc tooling (never a prod dep)
    src/{conformance,faults,fixtures,doctor,fake,alloc_tracking}/
```

Boundary rules (hexagonal direction is inward-only):

- **`domain/`** is pure: no I/O, no `std::fs`, no `std::env`, no wall-clock
  (`SystemTime::now` / `Instant::now`), and it must NOT import `crate::adapters`.
  It depends on its own types plus the `ports/` trait shapes.
- **`ports/`** holds trait definitions only — no concrete adapters, no I/O.
- **`adapters/`** implement port traits; infra types (hdrhistogram, metrics) live
  here. Allocator telemetry from adapters is **advisory**: it never mutates ledger
  counters.
- **`application/`** orchestrates domain + ports; carries no host nouns.
- **`api/`** is the public broker surface, builder-first. Low-level broker
  backdoors stay `pub(crate)` / unexported.
- **`facade`** composes core behind builders; storage backings (redb, moka, scc,
  bumpalo) are feature-gated and confined to their `*/backings/` modules.
- **`testkit`** is NEVER a mandatory production dependency. `alloc_tracking` (the
  only `tracking-allocator` integration) is feature-gated so it can never enter a
  production graph.

Forbidden usages (fail-closed under `-D warnings` + repo-local doctor + deny):

- Semantica nouns in the public API (`Semantica*`, `quanta_runtime`, `codegraph`).
  The portable library carries none.
- `core` depending on `facade`/`testkit`; `facade` depending on `testkit`.
- A path dependency escaping the workspace (breaks extraction).
- `crate::adapters` imported from `domain/` or `ports/`.
- Raw constructor backdoors leaking past the builder-first surface; stale
  `V1`/`V2` / renamed-symbol naming (the doctor rail flags both).

Enforcement: `cargo clippy --workspace --all-targets --all-features -- -D warnings`,
`cargo deny --all-features check`, `scripts/memory-platform-doctor`, and the
extraction pre-flight in `scripts/extract-to-standalone-repo.sh` (member
presence, dependency direction, no escaping path deps, self-hosting file set,
and `cargo metadata` resolves). If a change needs a NEW crate edge, stop and
reconsider — do not add the import to make it compile.

## Test Topology

Tests must **catch real regressions** in budget accounting, policy resolution,
pressure/scheduling, and the portable stores — not merely import modules.

Placement:

| If it proves… | Put it in… |
| --- | --- |
| Ledger reserve/commit/release + the 4 invariants | `core/src/domain/ledger.rs` `#[cfg(test)]` |
| Policy / manifest / preset / residency validation | `core/src/domain/{policy,config}.rs` `#[cfg(test)]` |
| Pressure controller / scheduler behavior | `core/src/application/{controller,scheduler}.rs` `#[cfg(test)]` |
| Public broker surface end-to-end (reserve→commit→snapshot→release→rebuild) | `core/src/api/control.rs` `#[cfg(test)]` |
| Cross-cutting policy contracts | `core/tests/wave1_policy_contracts.rs` |
| A facade store / pipeline behavior | that feature's `service.rs` `#[cfg(test)]` |
| A storage backing (redb/moka/scc) round-trip | the backing module under its feature |
| "the conformance suite actually bites" | `testkit` conformance + `self_tests` |
| Deterministic fault/chaos scenarios | `testkit/src/faults/` |

Conventions:

- **Conformance must bite.** The testkit's meta-requirement: feed a deliberately
  broken/lying fake into the public suite and assert it is REJECTED, alongside the
  honest-fake and real-broker positive cases. A suite that passes everything is
  worthless — preserve this when extending.
- **Assert invariants, not vibes.** After an op, assert the ledger invariants
  (`total_owner_bytes`, class/owner balance) hold — not just that a call returned
  `Ok`. No `assert!(true)` / `assert_eq!(x, x)` placeholders.
- **Assert on the `MemoryError` variant**, not on stringly-typed message
  substrings where avoidable.
- **Feature-gate tests** with the feature they exercise; `--all-features` must be
  green and each feature must build alone.
- `#[ignore]` needs a reason: `#[ignore = "<why>"]`.

## Determinism & Accounting Invariants

The ledger (`core/src/domain/ledger.rs`) is the semantic accounting SSOT. It is
single-threaded and synchronous; the public broker wraps it behind a lock. Its
behavior must be **deterministic and reproducible** for the same operation
sequence — conformance suites and fault fixtures depend on it.

Global invariants (must hold after every committed operation):

1. `sum(class usage) == sum(owner usage)`
2. `sum(owner usage) == retained payload bytes + retained metadata bytes
   + live scratch reservations`  (the `ChargeKind` partition)
3. `reserved <= soft <= hard`  (validated when the policy is installed)
4. No live writes while `rebuild_in_progress`

Rules:

- **Fail-closed before mutation.** Validate the whole operation first; every
  mutating op either fully succeeds or leaves the ledger untouched. Never mutate
  partway and then return `Err`.
- **Telemetry is advisory.** Allocator telemetry (hdrhistogram/metrics adapters)
  never mutates ledger counters — it only observes.
- **Stable ordering.** Anything iterated for a snapshot, report, or assertion uses
  ordered containers (`BTreeMap`) or an explicit sort. Do not depend on `HashMap`
  iteration order for snapshots, `LedgerSnapshot`, `EffectiveBudgetReport`, or
  conformance output.
- **Deterministic fixtures.** `testkit` fault/chaos scenarios are deterministic —
  no timing heuristics, no wall-clock, no RNG driving outcomes. A scenario that
  "sometimes" fails is a bug.
- **Checked arithmetic on counters.** Byte/budget math uses `checked_*` /
  `saturating_*` per the documented invariant — never silent wrap or lossy `as`.

### No silent heuristics

- **Override resolution:** the effective-budget resolver layers overrides by an
  explicit, documented precedence (`OverrideSource`); do not infer precedence
  from map order.
- **Capacity decisions:** an over-budget reserve returns `MemoryError::Capacity`,
  not a silently clamped or partial reservation.
- **Conformance must bite:** a suite that passes everything is worthless — the
  testkit proves it REJECTS a broken/lying fake as well as accepting an honest
  one. Keep that property when extending it.

## Error Handling

A memory-accounting platform that **drops failures quietly** corrupts the ledger.
Fail loudly and fail-closed.

The single error type is `MemoryError` (`core/src/domain/errors.rs`):

```text
MemoryError = Build | Config | Capacity | InvalidState | Report | Unsupported
MemoryResult<T> = Result<T, MemoryError>
```

Domain-intent aliases all resolve to `MemoryError`: `CapacityError`, `PinError`,
`PublishError`, `StoreWriteError`, `StoreDeleteError`. Construct via the helpers
(`MemoryError::config("…")`, `::capacity("…")`, `::build("…")`, `::report("…")`).

Principles:

- **No silent recovery.** Production code must not coerce a capacity / config /
  invalid-state failure into an empty default or a swallowed `Ok`.
- **Fail-closed before mutation.** An over-budget reserve, an invalid policy, or a
  write during rebuild returns the appropriate `MemoryError` BEFORE touching the
  ledger — never half-apply then error.
- **Preserve the source.** When wrapping a backing error (redb/moka/scc), include
  it: `format!("spill write failed: {e}")`. Never `map_err(|_| …)`.
- **Pick the right variant.** Over-budget → `Capacity`; bad manifest/policy →
  `Config`; builder misuse → `Build`; operation illegal in current state (e.g.
  write during rebuild) → `InvalidState`; snapshot/report failure → `Report`;
  not-wired capability → `Unsupported`.

Rust patterns:

| Avoid | Prefer |
| --- | --- |
| `.unwrap()` in non-test code | `?` with a `MemoryError` variant, or `.ok_or_else(...)` |
| `.expect("")` / `.expect("TODO")` | tests only, with `.expect("<invariant that cannot fail>")` |
| `Err(_) => {}` / `let _ = fallible();` | propagate with `?` or map to a typed error |
| `panic!()` / `todo!()` in shipping paths | return `MemoryError` with an explicit variant |
| `map_err(|_| MemoryError::…)` | `map_err(|e| MemoryError::…(format!("…: {e}")))` |
| lossy `as` / wrapping math on counters | `try_from` + `checked_*` / `saturating_*` |

`MemoryError` derives `Clone, Debug, PartialEq, Eq` and implements
`std::error::Error` + `Display` — assert on the variant in tests, not on string
substrings where avoidable.

## Dependency Policy

Runtime dependencies are declared in each crate's `Cargo.toml`, pinned in the
root `[workspace.dependencies]`, and audited by `cargo deny --all-features check`
against `deny.toml`.

**Shared versions** (pin in root `[workspace.dependencies]`, opt in per crate):

- `bumpalo` — facade `payload_store` scratch arena
- `moka`, `scc` — facade `revocable_store` backings
- `redb` — facade `spill` backing
- `hdrhistogram`, `metrics` — core `telemetry` adapters
- `tracking-allocator` — testkit `alloc_tracking` ONLY

**Rules:**

- Every non-trivial third-party crate is **optional** and behind a feature gate.
  `core` and `facade` build with `--no-default-features` and pull infra crates in
  only via their feature (`telemetry`, `spill`, `revocable_store`, …).
- `tracking-allocator` may appear ONLY under testkit `alloc_tracking`; it must
  never reach a production dependency graph.
- New runtime deps must pass `cargo deny --all-features check`. `deny.toml`
  allows only licenses actually encountered in the `--all-features` graph, so an
  unused allowance warns and a newly introduced license fails closed. If you add
  a dep with a new license, add it to the allow-list with a one-line rationale.
- Stay inside the architecture edges (`core <- facade <- testkit`). Do not add a
  dependency that pulls in Semantica/host crates — that inverts the direction.
- No dependency may introduce a path dep escaping the workspace (breaks
  extraction). Inter-member deps stay relative within `crates/`.

`deny.toml` notes: private (unpublished) members are license-exempt
(`license = "UNLICENSED"`); `multiple-versions = "allow"`. MPL-2.0
(tracking-allocator) and LGPL-2.1-or-later (transitive) are accepted for this
internal library — revisit if either reaches a distributed binary.
