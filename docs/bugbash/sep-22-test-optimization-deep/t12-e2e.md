## Findings

### T12-01 [C/M] Concurrency e2e is the scope's wall-clock + flake hotspot (lens C)
- Opened: `crates/quanta-memory-platform-facade/tests/hellgate_e2e.rs:332`
- Oracle (quoted, `:348-354`):
  ```
  match store.insert_checked(format!("k{t}-{i}"), vec![0u8; 1_000]) {
      Ok(()) | Err(MemoryError::Capacity(_)) => break,
      Err(MemoryError::OperationInProgress(_)) => {
  ```
  plus `:352 assert!(busy_retries < 100_000, "store never left busy phase")`.
- Mechanism: 8 threads × 50 inserts × 1 KB payloads with a `yield_now` busy-retry spin; spin count is scheduler-dependent and the 100k tripwire is a busy-loop cliff, not a typed wait. 400 contended charged inserts dominate this scope's runtime (scope absent from top-40, so this is a within-scope hotspot, not a workspace hotspot).
- Action: shrink to 4 threads × 25 inserts, replace `yield_now` spin with small capped backoff; keeper stays in place (`hellgate_e2e.rs:332`). Est. saving: ~50% of this test's wall-clock, minus flake surface.

### T12-02 [C/S] Reconfigure e2e moves megabytes unnecessarily (lens C)
- Opened: `crates/quanta-memory-platform-facade/tests/hellgate_e2e.rs:295`
- Oracle (quoted, `:298` + `:320`):
  ```
  store.insert_checked("x".to_string(), vec![0u8; 600_000]).expect("600k under 1M class cap");
  .insert_checked("y".to_string(), vec![0u8; 3_000_000])
  ```
- Mechanism: 600 KB + 3 MB payloads only need to sit on either side of the 1M→4M cap boundary; same boundary crossings work at ~60 KB/300 KB with adjusted caps.
- Action: shrink payloads 10× (adjust caps to preserve crossings); keeper `hellgate_e2e.rs:295`. Est. saving: ~3.5 MB alloc + memcpy per run, trivial time but real allocator pressure in parallel suites.
